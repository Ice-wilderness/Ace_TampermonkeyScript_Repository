## Context

目标脚本 `scripts/Discuz 论坛帖子已读标记与图片预览.js` 已有 GM 存储配置、设置面板、列表页识别逻辑和 `GM_addStyle` 注入的基础样式。当前脚本会在 Discuz 列表页处理 `threadlisttableid` 下的帖子行，但不会调整页面主容器宽度。

Discuz 论坛常用 `.wp` 作为页面主体容器，许多老论坛把 `.wp` 写死为较窄的像素宽度。新功能需要给用户一个默认关闭的开关，启用后在帖子列表页调整指定容器宽度，并保留对非标准论坛 DOM 的自定义选择器能力。

## Goals / Non-Goals

**Goals:**
- 在现有设置面板中新增帖子列表宽度控制配置。
- 默认关闭该功能，避免改变现有用户页面布局。
- 默认目标选择器为 `.wp`，并允许用户改为其他 CSS 选择器。
- 支持百分比宽度和固定像素宽度。
- 支持默认配置和当前站点策略，当前站点可以选择使用默认配置、使用独立配置或不启用宽度控制。
- 只在帖子列表页应用宽度控制。

**Non-Goals:**
- 不调整帖子详情页宽度。
- 不新增站点匹配范围、外部依赖或跨域权限。
- 不改变已读标记、图片预览、导入导出或已有 GM 数据结构。
- 不自动探测所有 Discuz 主题的最佳容器。

## Decisions

1. 使用独立 GM 设置键保存配置。

   计划新增类似以下默认配置键：`thread_list_width_enabled`、`thread_list_width_selector`、`thread_list_width_mode`、`thread_list_width_value`。这些键只保存用户设置，不迁移或改写现有已读数据、预览设置和浮动按钮位置。

   备选方案是把新设置并入一个聚合配置对象，但脚本现有设置多为独立 GM key；继续沿用独立 key 可以保持改动更小。

2. 使用默认配置 + 当前站点策略配置。

   现有 `thread_list_width_*` 键作为默认配置保留；当前站点使用 `thread_list_width_site_policy_<hostName>` 保存三态策略：`default` 表示使用默认配置，`site` 表示使用当前站点独立配置并启用宽度控制，`disabled` 表示当前站点强制不启用。站点独立配置继续使用带 `hostName` 后缀的站点级配置键保存选择器、宽度类型和宽度值。

   备选方案是为所有站点维护一个配置 map，但这会改变现有独立 key 风格，并增加导入导出和迁移复杂度。按站点分散 key 更贴合现有脚本。

3. 默认选择器使用 `.wp`，自定义选择器通过 `querySelectorAll` 应用。

   启用后函数读取选择器，空值回退到 `.wp`。实现时应使用 `document.querySelectorAll` 查找目标元素，并捕获无效选择器异常；无效或未匹配时不抛错，不影响列表页其他功能。

   备选方案是直接拼接选择器并用 `GM_addStyle` 注入 CSS，但用户自定义选择器若包含非法内容会影响整段样式。查询 DOM 后设置内联样式更容易隔离失败。

4. 宽度值按模式格式化后设置到目标容器。

   百分比模式把数值格式化为 `<n>%`，像素模式格式化为 `<n>px`。为覆盖老论坛主题的固定宽度，目标元素应至少设置 `width`，并可同时清理或覆盖 `max-width`；为了保持常见居中布局，可设置左右 `margin` 为 `auto`。

   备选方案是只设置 `max-width`，但很多 Discuz 老主题固定的是 `width`，仅改 `max-width` 不能解决窄屏容器问题。

5. 设置面板复用现有 UI 工厂函数并少量补充输入控件。

   现有设置面板已经有 checkbox、number input、select 和分区布局。新功能可以新增一个“帖子列表宽度”分区；若需要选择器文本输入，可增加一个小型文本字段工厂函数，样式复用 `.settings-field`。

## Risks / Trade-offs

- [Risk] 用户选择器匹配到过多或错误元素，可能改变论坛页面其他区域布局。→ 默认关闭；设置文案提示默认 `.wp`，自定义选择器由用户按站点调整。
- [Risk] 个别论坛主题使用更高优先级 CSS 或脚本后续改写宽度。→ 采用内联样式，并在列表页初始化阶段调用；本次不引入持续轮询，避免性能和副作用扩大。
- [Risk] 百分比或像素值输入异常。→ 保存时按模式进行数值校验和范围限制，读取时也使用默认值兜底。
- [Risk] 自定义选择器无效。→ 捕获异常并静默跳过宽度应用，其他功能继续运行。
- [Risk] 用户误以为当前站点策略会影响默认配置。→ 使用“当前站点策略”下拉框明确区分“使用默认配置”“使用独立配置”“不启用”。
