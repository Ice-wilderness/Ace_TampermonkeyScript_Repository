## Purpose

让用户直接从失败站点定位问题，查看脚本自身签到尝试的分类原因、阶段和脱敏请求信息。保留现有短期诊断日志与导出能力，同时严格区别于开发工具的网页全量抓包和签到 API 候选探测。

## ADDED Requirements

### Requirement: 单站点失败诊断入口

控制台 MUST 为失败、适配异常和结果未知的目标提供诊断入口，按站点显示近期签到尝试的时间、阶段、错误类别、尝试次数及已有请求摘要，并支持导出该站点记录。

#### Scenario: 用户查看一个失败目标
- **WHEN** 用户从目标行打开诊断
- **THEN** 控制台 MUST 只显示该目标近期相关记录
- **AND** MUST 提供与原因相符的登录、人工检查、重新检查或重试建议

#### Scenario: 当前站点没有请求记录
- **WHEN** 失败来自页面按钮或 DOM 检测且没有请求日志
- **THEN** 诊断 MUST 显示已有阶段与原因并说明没有请求记录
- **AND** MUST NOT 为补齐日志自动重复提交签到

### Requirement: 敏感信息统一脱敏

日志持久化、界面显示及导出 MUST 对凭据和验证字段统一脱敏，覆盖 Cookie、Authorization、令牌、formhash、safeid、nonce 和 `_nonce`，包括 URL、请求体、响应头与响应内容中的可识别字段。

#### Scenario: 次元狗请求包含 nonce
- **WHEN** 诊断记录中的 URL 或请求体包含 `_nonce` 值
- **THEN** 保存、显示和导出的记录 MUST 隐去该值
- **AND** MUST 保留字段名、请求阶段和结果等非敏感诊断信息

#### Scenario: 导出升级前日志
- **WHEN** 升级前的日志包含当前规则能够识别的敏感字段
- **THEN** 读取、展示和导出时 MUST 再次执行脱敏
- **AND** MUST NOT 原样输出旧敏感值

### Requirement: 短期保留和按目标诊断归属

日志 MUST 继续遵守最近三天及容量上限的保留规则；并发任务的请求 MUST 归属各自站点和尝试，诊断清空与导出 MUST NOT 改变签到状态。

#### Scenario: 多站点同时失败
- **WHEN** 多个目标的请求与重试交错完成
- **THEN** 每条诊断 MUST 属于发起它的站点和尝试
- **AND** 按站点导出 MUST NOT 混入其他目标的请求

#### Scenario: 用户清空诊断
- **WHEN** 用户清空失败日志
- **THEN** 已有签到成功日期、配置和每日状态 MUST 保持不变

### Requirement: 诊断不扩展为网页 API 探测

正式脚本 MUST 仅记录自身签到流程中的请求与状态；诊断入口 MUST NOT 安装全网页请求拦截、收集 API 候选或修改开发侧探测工具的数据。

#### Scenario: 用户查看已有日志
- **WHEN** 用户打开单站点诊断或导出日志
- **THEN** 脚本 MUST 只读取现有诊断数据
- **AND** MUST NOT 启动网页全量抓包或 API 候选探测
