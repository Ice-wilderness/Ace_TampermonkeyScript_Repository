## Context

动机见 proposal.md。现有实现约 2100 行，CSS 与业务共处一个 IIFE，已有 PreviewState、WeakMap、IntersectionObserver、自动页面请求队列和 sessionStorage 缓存，可以渐进重构。

已核对的代码问题：状态散落在对象、dataset 和内联 display 中；看图写入分布在多个操作入口；批次结束才呈现图片但每页立即推进 loadedPageUntil；请求仅检查 HTTP 状态；destroy 没有调用；图片尺寸轮询无超时；存储键依赖 document.title；足迹整表读改写；导出捕获面板打开时的快照。以上是静态分析结论，真实论坛验证仍需在实施时完成。

仓库现有 Discuz 规范仅覆盖列表宽度。该规范全部保留；未发现此脚本的专用测试。实现继续交付单个用户脚本，测试夹具独立放在 tools/discuz-helper/。

## Goals / Non-Goals

**Goals:**

- 让所有视图由明确状态驱动，加载、错误和阅读标记可解释且可恢复。
- 在论坛原有列表上提供协调的阅读辅助视觉，不干扰原站导航、排序和帖子链接。
- 以可重现的夹具验证失败恢复、并发、迁移和布局，避免仅凭正常网络下的截图验收。

**Non-Goals:**

- 不重写论坛页面，不增加 React、构建发布链、远程字体、图标库、云同步或跨域抓取。
- 不增加书签、全文阅读器、自动翻论坛列表页、图片下载器或无限抓取全部帖子页。
- 不实现任意 Discuz 主题的全面适配；对无法确认结构的页面安全降级。

## Decisions

### 1. 单文件内分层，状态作为唯一事实来源

划分 PageAdapter、HistoryStore、PreviewCache、RequestScheduler、PreviewController 和视图创建／渲染职责。保留轻量函数和对象组织方式，不引入框架；相比整体组件框架迁移，能减少与原站 DOM 的边界问题。

每帖状态包含生命周期代次、展开状态、交互意图、逐页抓取结果、逐图呈现结果及错误。页面状态使用 idle / queued / fetching / ready / failed，图片使用 queued / loading / ready / filtered / failed；disposed 是控制器终态。显示状态只由这些数据派生，DOM dataset 仅供调试与样式使用。请求完成不等于图片呈现，折叠不等于销毁。

### 2. 视觉方向：带细节的克制阅读工具

默认采用暖白背景、墨色文字和低饱和青绿色强调色，深色使用炭灰背景与较亮青绿；错误独立用红色，不以大面积灰底覆盖帖子。建议初始 token 为浅色 #F7F8F5 / #FFFFFF / #202A2A / #277C72，深色 #171D1D / #222B2A / #E7EEEB / #72C8B6，实施时以对比度与实际截图校正。主题默认跟随系统，提供浅色、深色强制选项以适配网站主题差异。

- 中文正文采用本地可用的苹方、微软雅黑等字体，标题适度加重，通过字号、字重和留白建立层级。相比下载品牌字体，此工具优先保证无外部请求和中文可读性。
- 统一 4/8/12/16/24 间距、8–12 圆角、细边框、轻阴影；图标使用少量内联 SVG，替换混用 emoji 的主要操作入口。
- 设置面板桌面采用左侧分类导航、右侧内容，窄屏改为顶部可换行分类；分类为外观、图片预览、已读样式、列表宽度、数据管理。底部保存区保持可见，数据危险操作与普通设置分开。
- 纯外观设置提供临时预览，取消还原；保存外观无需刷新。影响任务的设置在保存后使相关任务失效并重建；确需刷新时明确提示且由用户触发，不自动倒计时刷新。
- 列表使用小型文字状态标记、紧凑操作入口，预览使用独立横向区域；加载更多改为清晰页尾操作，避免依赖最后一张图测量按钮高度。
- 图片默认完整适配固定比例卡片，长图不裁切关键信息；保留已知尺寸用于稳定占位。宽屏多列，390px 下允许单列，避免网格最小宽度撑破页面。
- 灯箱为深色画布、明显关闭按钮、左右导航、计数与失败重试；保留图片左右半区点击和方向键操作。关闭后恢复焦点；对話框限制焦点、支持 Esc，尊重减少动画偏好。
- 样式统一使用 dh 前缀并限定到脚本根节点；正文标记选择器明确限定帖子标题及元信息。暂不采用 Shadow DOM，便于与原站表格和标记交互。

### 3. 独立挂载与页面适配

标准表格在对应帖子的 tbody 内追加由脚本持有的 tr/td，按原行实际列跨度设置 colspan。这样保持与帖子的移动、隐藏关系，又不挤占标题 th；已读透明度仅作用于原帖子内容。非标准结构只在能确认安全容器时挂载，否则保留标记及设置并停用该条预览，不改写原站表格。

集中识别列表、有效详情正文、标题链接及分页；URL 使用 URL 对象解析，伪静态路径翻页优先于附加查询参数，保留无关参数。图片地址以实际响应 URL 为基准规范化后去重，限制为 HTTP(S)，保留已有高清／懒加载属性优先级。

列表监听从初始化即启用，处理新增、移除、容器替换和节点复用；检查脚本所有权标识避免响应自己的插入。对新增节点批量增量处理，容器替换时才全量重建。不泛化为任意 SPA 路由支持。

### 4. 看图意图与成功呈现组合判定

自动加载、展开预览、加载更多和重试缩略图均不生成看图意图。只有点击合格缩略图打开灯箱才生成当前控制器代次内的意图，并在灯箱目标图成功显示后写入 viewedImages。收起再展开、无图、失败或已销毁的异步回调均不写入。

真实访问只在有效详情正文被识别后写入 visited，权限或验证页不记录。已访问优先显示，两个字段独立保存。恢复未读只重置 visited，清除看图只重置 viewedImages；均提供 5 秒撤销。清除看图会撤销当前意图，后续自动结果不重新标记；新的主动操作可以再次标记。隐藏已读模式提供“临时显示已隐藏帖子”入口，使重置操作仍可到达。

### 5. 分页与错误恢复

每页成功后立即写入页结果并提交候选图，抓取页集合与呈现图片集合分离；连续成功页进度由页结果计算。批量第 3 页失败时前两页继续可见；重试复用前两页，仅请求失败页，不跳过未呈现图片。后续分页仍默认关闭，开启后每次最多 3 页，自动预览只请求第 1 页，默认最多显示 5 张有效图片。

返回内容必须存在可识别正文，且不为可识别的登录／权限／验证界面。无法确定时返回“页面无法识别”，不声称无图，不绕过访问限制。区分 network、timeout、http、auth、challenge、unrecognized、empty、filtered、image-failed 和 partial；用户文案隐藏内部错误码。

只有有效正文的页结果进入缓存；真正无图可缓存，访问限制与解析错误不缓存。缓存沿用会话存储，采用逐页时间戳、24 小时 TTL，读取时清除过期项，写入前按最近使用清理；默认最多 100 帖且序列化总量不超过 2 MiB。配额失败只影响缓存，不中断预览。提供当前帖重新获取入口以处理新回复或旧缓存。

### 6. 分离页面与图片调度，明确取消边界

所有页面请求共享现有并发配置（1–5，默认 1），排队手动任务优先，自动任务启动保留最小 300ms 间隔。图片单独限制同时启动数量，初始上限 4，不把该内部预算再暴露为必填设置。前台灯箱目标图优先于缩略图，保留已有结果，不为装饰进行额外预取。

页面请求用 AbortController，默认 15 秒超时；网络、超时和 5xx 最多自动重试 1 次并退避 1 秒。429 遵守可解析的 Retry-After 并暂停自动调度；没有有效提示时暂停 30 秒。权限、验证及解析失败不自动重试。图片默认 20 秒超时，失败保留可重试状态；仅允许有限尺寸检测，必须随完成／超时／销毁停止。

后台暂停新增自动页面和缩略图任务，已开始任务允许在超时内完成。折叠暂停该帖未开始的图片任务；移除帖子时取消其页面请求、观察器、计时器及排队任务。图片网络无法保证由浏览器真正中断，解除回调并以代次校验阻止旧结果回写；不将清理引用等同于网络已取消。

### 7. 稳定站点标识与细粒度持久化

站点 ID 使用精确保留的 hostname（含非默认端口）和经 forum.php／伪静态链接确认的论坛安装路径，编码而非将标点统一替换为下划线。HTTP 与 HTTPS 同主机同路径共享记录，子目录论坛隔离，标题只作显示名。无法确认安装路径时不自动合并不确定旧记录。

使用版本化前缀和每帖每状态字段独立存储，字段保存布尔值、更新时间与操作标识；同一字段按最后成功持久化的操作生效，不宣称全局事务。不同帖子或 visited/viewedImages 更新不再整表覆盖。索引仅为可重建缓存，GM_listValues 枚举为记录发现依据；新增该权限用于记录枚举及旧键发现，不增加监听权限，页面恢复可见时重新读取并更新标记。

单帖重置保存显式 false；清空使用站点数据代次，旧标签页提交前重新读取代次，旧代次结果不回写。清理先核对最新字段标识，保留并发更新过的记录。撤销仅在目标字段仍是本次重置结果时恢复，避免覆盖另一标签页的新操作。保留现有约 2000 条历史的清理策略，清理围绕完整帖子而非孤立字段计数；不无限增长。

迁移只导入尚未初始化的字段，已迁移／已重置字段不能被旧快照重新复活。保留原键及迁移完成标志，读回验证后才启用新结构。标题导致的多个同主机旧键可枚举发现；同主机多论坛或旧键无法判断归属时，通过数据管理提示选择旧数据导入当前论坛，不静默合并。

相比继续整表写回，这一方案缩小了冲突范围；相比追加无界操作日志，不需要复杂压缩协议。必须以可控的多标签页交错测试验证边界，不能用写后一次读取宣称并发安全。

### 8. 导入导出与操作反馈

导出时读取最新已提交记录，默认使用包含 schemaVersion、siteId、exportedAt 和 records 的 JSON，提供旧格式导出供回退使用，释放对象 URL。继续接受原有 tid 映射及布尔旧记录。

导入先完整解析和校验，再展示新增／更新／跳过统计后执行合并：tid 必须为正整数文本，拒绝原型相关键，记录必须为布尔旧值或合法对象，时间戳必须为有限非负数；拒绝 null、数组、超限文件（默认 5 MiB）和不支持版本，不留下部分导入。异站点文件明确提示归属并由用户选择是否合并，不自动重定位站点。新格式按字段时间合并，旧格式按记录时间兼容读取，不用旧布尔值覆盖新字段重置。

导入、清理与清空后立即刷新统计和列表，不依赖刷新页面。存储写入失败保留原数据并给出失败反馈，不伪报成功。

## Risks / Trade-offs

- [真实主题结构未实测] → 使用标准、窄屏、深色及自定义表格夹具，再选择用户现有可访问论坛做只读验证；无真实站点时明确保留验证缺口。
- [新增 GM_listValues 导致管理器提示权限更新] → 只增加这一项必要权限，实施时同步头部；收尾说明用途。
- [独立存储项增多] → 按站点前缀枚举、缓存结果、维护可重建索引、保留记录上限；用 2201 条以上记录验证清理和面板打开表现。
- [GM 存储没有跨键事务] → 定义字段与代次边界，用交错测试覆盖清空／写入、重置／撤销及迁移，不承诺任意故障下的数据库级原子性。
- [取消后图片请求可能继续] → 调度限流、超时与陈旧结果隔离共同限制影响，不循环重试图片。
- [同时重构视觉和行为使定位困难] → 按状态与数据、请求流程、页面挂载、视觉组件顺序实施，每阶段运行针对性回归。

## Migration Plan

1. 建立当前行为夹具及旧数据样本，再实现新存储适配与状态规则，暂保留既有视图验证核心路径。
2. 完成页面与图片流程后替换挂载和 UI；每次替换仅调整本脚本区域。
3. 首次升级保留旧键，导入新结构、读回核对后标记迁移完成。中断后可重入，明确重置字段不被回灌。
4. 新结构读取或写入失败时进入可说明的数据错误状态，允许导出可读数据，不静默清空。
5. 回退旧脚本前导出旧格式最新数据；原键作为升级前快照可恢复，升级后新增记录须通过导出导入保留，不承诺旧脚本自动读取新结构。
6. 实施结束先交付验证结果；用户另行要求收尾时再统一更新版本、README、CHANGELOG，并检查全部 userscript 元信息。
