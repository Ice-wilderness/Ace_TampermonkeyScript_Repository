# Proposal

## Why

现有 Bilibili 观看历史仅保存在当前浏览器，手动导出不便于多设备接续观看，localStorage 临时备份也不能用于按日期完整回滚。增加轻量 WebDAV 同步和自动日期备份，让用户自行选择云端存储，并在误删后恢复历史。

## What Changes

- 分别提供 WebDAV 地址、保存目录、用户名、密码／应用密码配置；在保存目录下自动创建本脚本专用的 `bilibili-history/` 子目录，并提供关闭、每小时、每天的自动同步选项和立即同步操作。
- 双向合并观看记录及删除标记；手动删除和保留周期清理均跨设备传播，沿用现有记录版本排序。
- 在有匹配页面运行时按间隔同步，重新打开页面后补一次到期任务，不承诺浏览器关闭时执行。
- 日常自动同步、备份及失败重试静默进行，状态仅在云同步模块查看；需要本地／云端二选一时暂停同步并保留待处理入口，不自动弹窗打断观看。
- 大量历史的序列化、解析、摘要与 gzip 处理放入单个临时 Worker，主线程分批读取和提交；日常播放保存不等待云同步，未到期检查不扫描全部历史。
- 默认每日首次成功同步保存一份日期备份，默认保留最近 7 天，用户可修改保留天数；每日备份和操作前备份使用同一保留设置，无页面运行的日期不生成虚构备份。
- 云端快照和备份统一采用 gzip 压缩的紧凑 JSON；每轮先读取小型 state.json，以 UUID 判断云端版本；本地已完整采用同版本时无需下载历史正文；内容相同不重复上传，当天已有备份时不重复提交文件正文。
- ETag 和条件写入作为可选增强，不作为连接门槛；缺少时自动采用小索引检查后按需读取—合并—上传的兼容模式。用户已接受该模式下多设备同时写入可能覆盖的限制，包括回滚和删除清理；不增加锁或复杂并发协议，能力状态仅在云同步模块显示。
- 更新先上传唯一命名的完整历史文件，成功后才发布索引；定期清理未被引用的旧同步文件，日期备份独立保留，避免版本文件永久积累。
- 删除标记在成功进入云端后保留 30 天再回收，配合一个清理进度防止旧记录复活；错过删除信息的设备暂停自动合并，由用户二选一使用本地或云端完整记录，操作前备份两边。
- 同时整理本地已安全回收的删除项和旧提交，避免只缩小云文件、本地仍持续积累；删除标记窗口与可配置的备份保留天数独立。
- 支持选择已有日期备份完整回滚，回滚前自动保存当前状态；所有设备下次同步采用回滚后的历史，包括替换离线设备未同步的旧记录。
- 新增与偏好设置、历史管理、数据统计并列的“云同步”独立模块，不放在维护分类；集中呈现状态、连接配置、同步策略和备份恢复。
- 云同步沿用现有深石墨导航、暖白背景、蓝色主操作及字号间距体系，采用经过设计的状态区、分段选项、表单和备份列表；避免默认浏览器控件外观及原生 alert／confirm／prompt，保留语义与键盘可访问性。
- 保持实现精简：全量 JSON 快照、现有提交机制、必要的格式校验和并发写入检查；不引入第三方 SDK、独立后台、增量操作日志、分布式锁或复杂重试。

## Capabilities

### New Capabilities

- `bilibili-history-webdav-sync`：配置、定时与手动双向同步、删除传播、日期备份和全设备回滚。

### Modified Capabilities

- `bilibili-history-storage-consistency`：明确临时恢复与显式云端回滚的边界，增加确认删除传播后的本地回收及旧采样隔离，保留普通导入与导出语义。
- `bilibili-history-manager-ui`：增加独立云同步模块与一致的定制控件，允许配置后的 WebDAV 请求，维持面板隔离与既有页面行为。

## Impact

- 实现范围：`scripts/Bilibili视频观看历史记录.js` 的 StorageManager／HistoryCommitStore 接口、管理面板导航及新增云同步页、AppController 生命周期；验证复用 `tools/bilibili-history/` 现有隔离测试。
- 新增专用 WebDAV 配置和同步状态 GM key，保留全部既有 key 和普通 JSON 导入导出格式；云端格式单独带版本、删除标记和回滚批次，不上传凭据、样式设置或调试日志。
- 新增 `GM_xmlhttpRequest` 权限和用户自定义服务器所需的 `@connect *`，不扩大匹配页面，不增加外部依赖。
- 服务端需支持标准 WebDAV 文件读写、目录列举和删除；条件写入与可信变更标识按实际能力启用，HEAD 不可用时使用 PROPFIND 或 GET。具体服务器兼容性在实施时验证。
- 本次仅生成提案、设计、规范及任务；不修改脚本、版本、README 或 CHANGELOG。后续实施也不自动触发发布收尾。
