## Why

新增或维护论坛签到站点时，手动翻浏览器控制台寻找签到 API 很慢，而且当天已经签到后往往无法直接复现完整请求。需要一个开发期诊断工具，帮助在以后新增站点时快速采集请求、表单、按钮、token 和响应线索，而不是把 API 探测做成日常用户功能。

## What Changes

- 新增项目内开发期 API 探测/诊断工具，用于辅助维护者为某个论坛站点研究签到接口，形态类似 Playwright/runner 工具，而不是油猴脚本内置功能。
- 工具应能临时捕获 fetch、XMLHttpRequest、表单提交和关键页面线索，并导出结构化报告。
- 工具应明确区分“候选线索”和“已验证 API”，不会自动改写每日签到状态，也不会自动启用站点 API 策略。
- 工具不嵌入每日签到控制台，也不进入发布给用户日常使用的 userscript；正常使用脚本时不显示、不运行、不采集。
- 后续真正把某个站点改成 API 签到或前台队列，应基于诊断报告另行实现，并继续保持保守成功校验。

## Capabilities

### New Capabilities
- `forum-signin-api-discovery`: 覆盖开发期 API 诊断、候选请求采集、页面线索采集、敏感信息脱敏和报告导出。

### Modified Capabilities

无。本变更不改变现有每日签到控制台的用户级需求；它只新增开发辅助能力。

## Impact

- 影响范围：新增仓库内开发辅助工具，服务于 `scripts/自用论坛辅助签到自写.js` 的后续站点维护。
- 不影响普通用户的每日签到控制台 UI、默认执行流程或当前站点状态记录。
- 不新增外部依赖；不要求把项目整体迁移为浏览器扩展。
- 如果后续某个站点基于报告改为 API 签到，才在对应实现阶段检查 `@connect`、`@grant`、README、CHANGELOG 和版本号。
