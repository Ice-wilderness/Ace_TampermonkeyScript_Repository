## Context

变更动机与已确认范围见 [proposal.md](./proposal.md)。本次以 `scripts/Bilibili视频观看历史记录.js` 的 3.5.1 为基线，继续交付单个独立用户脚本。

现有结构包括 `VideoKey` / `EpisodeResolver`、64 分片的 `StorageManager`、`VideoPlayerObserver`、`DOMWatcher` 和 `UIComponent`。管理面板由 `showManagerPanel()` 内的局部状态、模板和事件委托组成，CSS 由 `injectStyles()` 注入；无需引入构建系统或运行时框架。

上一轮使用原函数及模拟 GM / DOM 做了八组隔离验证：同分片两次写入仅余一条；只加载 P1 后漏查 P2/P3；80 个基础索引被部分内存覆盖为 7 个；五个未知视频触发五次重建；80% 正式进度被旧备份覆盖为 20%；无效导入留下部分内存变化；旧媒体进度写到新路由 key；关闭进度条后旧卡片仍保留进度条。这些是合成环境证据，真实站点时序与视觉表现留待实现后的浏览器验证。

已有 `bilibili-history-page-sync` 和 `bilibili-history-retention-cleanup` 继续作为行为基线。仓库已有 Playwright 开发依赖，但当前测试入口面向签到工具；本变更新建独立验证目录，不复用或修改签到测试。

## Goals / Non-Goals

**Goals:**

- 在现有匹配子域之间保证不同记录的并发提交不互相覆盖，同一记录按明确顺序收敛；失败批次不污染可见状态。
- 保留现有视频 key、公开记录字段、设置 key 及旧数据读取能力。
- 将界面状态、播放会话、存储提交与派生查询的生命周期分开，便于定向刷新和隔离测试。
- 为完整管理面板建立可以直接实施和截图验收的视觉与交互方案。

**Non-Goals:**

- 跨设备云同步、新站点适配、官方接口抓取、观看时长或逐次观看事件统计。
- 更换运行时框架、新增远程字体或图片服务、改写其他用户脚本。
- 承诺旧版脚本与新提交协议同时写入时的数据正确性；升级和回退需要处理仍运行的旧页面。
- 将整个页面封面、播放器和所有悬浮入口改成新的产品界面。管理面板、确认和反馈组件完整重构；页面标记修复更新逻辑，外部入口仅做必要的风格协调。

## Decisions

### 1. 使用独立持久化操作与可重建快照处理并发

GM 存储以脚本为范围，可跨匹配子域共享；值变更监听可以通知其他脚本实例，但文档没有提供条件交换或跨键事务保证。[Tampermonkey 存储文档](https://www.tampermonkey.net/documentation.php?locale=en&q=GM_values)支持这一能力边界。Web Locks 只协调同源上下文，不能单独保护 `www`、`space`、`t`、`search` 之间的共享数据，见 [Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)。

因此，不以“刷新缓存后整片覆盖”“GM 自增计数器”或“仅同源锁”作为可靠性基础。选择以下最小持久化协议，并由 `StorageManager` 封装：

| 数据 | 用途与约束 |
| --- | --- |
| 现有 `bvh_shard_0..63` | 保留为旧历史兼容基线；新协议不通过缓存整片覆盖它们来提交日常修改 |
| `bvh_tx_<id>_<shard>` | 事务的不可变数据块，保存该分片内的记录变更或删除标记 |
| `bvh_commit_<id>` | 不可变提交清单，列出数据块、数量和校验信息；数据块完整且清单已提交时才参与读取 |
| `bvh_checkpoint_<shard>_<id>` | 整理后的不可变分片快照，保留每条记录或删除标记的业务版本；同样通过提交清单发布 |
| `bvh_change_signal` | 最后一次变更提示，包含唯一提交标识及受影响范围；仅用于唤醒同步，不是唯一数据来源 |
| `bvh_base_index` | 可以失效和重建的派生索引，带完整性与覆盖范围信息；旧版索引作为升级输入，不直接信任其完整性 |

事务 id 使用每次实例启动生成的随机身份和本地递增序号，禁止多个实例覆盖同一个操作键。单记录保存也是一个事务。批量导入、删除、官方历史同步先准备数据块，再发布唯一提交清单；清单未成功确认时，不发布成功通知，也不修改供查询使用的已提交缓存。

每条变更包含来源、视频 key、完整公开记录或删除标记、采样/操作时刻以及稳定决胜信息。业务顺序在采样或有效操作准备时确定，重试、卸载补存和备份恢复必须沿用原顺序，不能通过重新生成“当前时间”把旧进度变成新进度。使用单实例单调时钟并吸收已观察版本；同一时刻按实例身份和序号稳定决胜。公开 `savedAt` 保持原语义，不作为所有来源的提交序号。旧基线的比较版本取其原有可解析时间，缺失时按未知旧版本处理，不能把迁移时间当成旧记录的新采样时间。

读取把旧基线、已提交操作和检查点按记录合并到有效视图；不同 key 独立保留，同一 key 使用业务版本决胜。异步 GM 写入完成后校验提交清单及块引用，再更新本地有效视图。存储 API 通过 Promise 适配层提供，优先使用 `GM.getValue`、`GM.setValue`、`GM.listValues`、`GM.deleteValue`；仅新增实际使用的授权。不能确认可靠提交的环境应报告失败并保留播放备份，不得静默退回会覆盖数据的写法。

新协议是多实例最终一致的记录存储，不宣称通用数据库的可串行化事务。不同来源的决策在提交准备时读取最新可见记录；若已观察版本在提交前变化，则重新评估该操作的适用性，播放采样本身的版本不因此变新。

**整理与垃圾回收：** 初始触发建议为待整理操作达到 128 个或 256 KiB，在空闲时间按受影响分片处理。检查点复制原记录版本，不能凭整理时间覆盖并发新记录。只有已确认的不可变替代副本完整保留了一个旧提交所有条目的相同或更高业务版本时，才可回收该提交；相同业务版本的物理副本使用严格全序选择保留者，防止两个整理实例互删唯一副本。对于多分片提交，必须确认全部数据块都已安全替代，再删除旧清单及其数据块；禁止提前删除部分块，使仍承载有效记录的原提交被误判为不完整。

删除标记保留最小 key 与版本信息，用于抑制旧基线、备份和延迟采样；不能仅因七天备份有效期已过就删除唯一的删除信息。未提交暂存块与正式记录分开计算；未提交暂存块不按时间自动删除；报告其数量及占用，仅在用户明确停止全部写入页面后执行离线清理。挂起事务恢复时重新检查并补齐块，才能提交。整理失败只保留冗余数据，不损伤有效历史。

**取舍：** 独立操作增加内部元数据和整理逻辑，但避免把冲突处理寄托在不具备原子性的全局索引或版本计数上。保留 64 分片读模型和旧数据，不要求用户手工迁移。

### 当前视频优先读取（性能回归后的设计修订）

用户进一步授权自动后台整理：局部初始化后自动安排独立存储实例执行完整校验与分组整理，不要求打开历史管理，也不占用前台写入队列。已确认的分组检查点作为可复用持久进度，关闭后继续校验并补齐；整理完成保存覆盖清单，后续只检查新增提交，跨组导入或累计提交达到阈值时再次整理。首次旧事务校验仍可能耗时，完成后才享有分组读取收益。跨页正确性沿用不可变提交、业务版本和完整覆盖回收，不假设存在互斥锁。

用户授权将视频启动从全量读取改为按需加载。视频页先加载当前 base 和关联分 P；其他卡片按可见查询请求合并加载。局部视图有独立范围标记，禁止写回完整索引；播放、访问、标题和备份提交只同步涉及范围。进入历史查询、统计、导出、删除或旧版快照操作时，明确升级为完整视图。

新提交清单包含涉及的 bases，完整派生索引增加按清单的 base 路由表与 coverage。定向读取只使用 coverage 内的派生路由排除无关提交；未覆盖的新清单仍读取元数据检查。命中提交后验证其全部数据块，保留批次完整性和删除标记。旧清单不带 bases 时使用完整旧索引及分片提示，并追查批次带出的其他 P 所在分片，避免遗漏删除标记；缺少可靠提示时保守读取。

检查点按 base 的固定散列分组发布，各组独立完整提交。一个旧事务只有在所有条目被完整覆盖后才整体回收，不把大事务拆成半可见结果。已经存在的全量旧检查点在首次命中时仍须完整校验；完整历史加载后后台整理自动转换为分组检查点。此兼容成本不能通过跳过完整性检查隐藏。

### 2. 按来源准备记录，并保留恢复证据

| 来源 | 准备与合并规则 |
| --- | --- |
| 本地播放 | 以确认会话的有效采样为准；新采样可以是更低百分比，支持从头重看；暂停、销毁和异常重试不刷新旧采样时间 |
| 官方历史 | 对最新可见记录继续执行“大于本地五个百分点才更新”；保留官方卡片观看时间，不伪造 currentTime；不满足条件则无事务 |
| localStorage 备份 | 先检查结构和七天有效期，再比较来源时间及删除状态；旧记录不覆盖新记录；失败不移除备份 |
| 文件导入 | 先校验整个文件，规范化后拒绝重复 key；合法旧数组、对象与当前导出均可读；提交前再次排除已有记录 |
| 删除 | 提交删除标记，同时移除当前源中对应的旧临时备份；其他源的旧备份由删除标记阻止恢复 |
| 撤销 | 保存本次删除的快照及提交身份；仅当当前仍是该删除结果时恢复，已有新记录则跳过并反馈数量 |

导入校验为独立纯函数，不调用写入方法或修改已提交缓存。拒绝 null、非记录对象、非有限数值、无效的显式时间和非法 key；百分比范围为 0 至 100，状态使用现有枚举。旧格式允许省略的字段按兼容规则补全一次；明确给出的错误字段不能靠默认值掩盖。错误反馈展示记录 key 和字段名，不显示实现堆栈。

新备份保留原采样/操作版本及事务身份，旧备份只能使用其可解析观看时间保守比较；同一时间且新旧关系不明时保留正式记录。备份写入自身也要捕获 localStorage 容量或访问错误，不能阻断播放器监听清理。

### 3. 索引明确完整性与有效覆盖范围

将现有的“base 是否存在于 Map”与“该 base 的所有分片是否加载完成”分开。派生索引记录完整标志、已覆盖的检查点/提交集合摘要、base 到目标分片的关系；内存另记每个 base 的加载状态和同一版本的在途查询。

- 查询已知 base 时，先加载所有关联分片，再返回去重且按分 P 稳定排序的 key。
- 索引完整有效且无该 base 时返回可靠空结果，不扫描 64 分片或写入索引。
- 索引缺失、旧格式无法证明完整或损坏时，在当前实例合并为一个分段重建任务；成功后才持久化完整索引。
- 索引持久化只能来自完整视图或基于完整视图的增量结果，不能把本页已加载的局部 Map 当成全部数据。
- 新提交、删除与恢复使受影响 base 的正负缓存失效。变更信号可能合并或遗漏中间事件，启动、切回及写入前通过提交键枚举补齐；全局数字 revision 只作为兼容提示。

否决通过频繁全量刷新“保证正确”的做法，因为它会放大历史页未知卡片查询的成本。已有 `_getShardId()` 保持不变，避免本次引入额外的历史重分片。

### 4. 播放身份按会话管理

在现有 `VideoPlayerObserver` 内引入会话身份和状态：`waiting`、`bound`、`switching`、`destroyed`。会话包含 generation、规范化 key、可用时的 cid、标题、媒体元素身份、媒体来源特征及最后有效采样。

路由变更先使当前会话进入切换态，再异步确认目标，不等待现有 500 ms 刷新后才隔离写入。`saveProgress()` 不再因为 URL key 改变就直接修改正在保存的记录 key。URL、激活分 P、页面可用元数据与媒体事件共同确认身份；DOM 状态缺失时保持等待，不能猜测。

同一媒体元素被复用时结合 `loadstart`、`emptied`、`loadedmetadata` 和可用媒体来源变化识别重新装载；站点自定义媒体元素不提供完整信息时，使用已有稳定分 P/媒体信息与会话 generation 保守绑定。真实站点验证要覆盖普通视频、多 P、合集和投稿播放列表。

销毁仅补存最后有效快照，清理等待观察器、重试、媒体事件和续播元数据回调。首次等待超时后保留可停止的低频发现过程；同会话媒体重建复用现有五秒自愈机制，避免叠加轮询。

`applyPendingSeek()`、续播提示和从头播放回调都绑定 generation；目标过期、会话结束或 key 不匹配即取消。标题在身份确认时取对应元数据，避免把旧 document.title 复制给新视频。

### 5. 数据通知、标记与查询分别失效

`onDataChange()` 返回取消订阅函数。变更事件携带 `changedKeys`、`changedBases`、`settingsChanged`、`fullReset` 和本地数据版本；去抖期间合并范围，不能只保留最后一次事件。管理面板实例关闭时调用统一 `dispose()`，取消订阅、计时任务与过期渲染。

页面标记维护渲染签名，包括视频 key、状态/进度、保存时间、分 P 详情摘要、目标封面节点和显示配置版本。文字相同但进度条、位置、透明度、颜色或提示变化时就地更新；结果没有变化时保留节点。

按基础视频维护页面元素关联；普通采样只让相关元素进入已有分批队列。全局显示配置变化才刷新全部可见元素，不可见元素再次进入视区时按最新签名更新。节点移除和路由变化清理强引用，避免引入新的长生命周期元素集合。

历史查询在数据版本下缓存轻量行模型：规范化 key、标题搜索文本、数值进度和数值时间。缓存键包括 query、status、sort；翻页和选择复用排序结果。数据变更先更新受影响行，再使相关查询与统计失效；一个版本的展开工作在历史和统计之间复用。

首屏框架同步建立；数据准备、过滤和大批量整理分段运行，初始每段以 8 至 12 ms 为预算。普通数组排序不可被一次 setTimeout 变为可中断操作：较大数据使用分块排序后合并，或复用已有排序索引。每次查询带 generation，旧结果、已关闭面板及旧数据版本的任务不再提交 DOM。

在 10000 条合成数据上记录脚本计算长任务、输入到结果耗时、读取次数和写入次数；将超过 50 ms 的脚本计算段列为需要修复的性能问题，并单列扩展存储调用耗时。重复翻页的全量读取和排序次数必须为零。统计范围保持 7/30/90 天，保留现有计数口径；“高进度占比”和“按最近保存时间”采用准确文案，不新增观看时长指标。

### 6. 以“观看记录工作台”重构完整管理面板

采用有明确层级的工具界面：窄幅深石墨导航承载三个入口，宽幅暖白内容承载配置或记录；蓝色集中用于当前导航、选中状态和主操作。预览区中的视频画幅和进度条成为与 Bilibili 场景相联系的视觉元素，正文维持克制的密度。

| --- | --- | --- | --- |
| 页头 | 标题、简短说明、未保存状态 | 标题、匹配数量、导入导出入口 | 标题、统计口径说明、范围选择 |
| 主内容 | 分组设置行＋标签预览 | 搜索筛选、记录列表、批量操作 | 数字摘要、分布图、近期趋势 |
| 底部 | 恢复默认、保存反馈、保存设置 | 条数、页码、翻页和每页数量 | 简短数据口径说明 |

不在导航或页头硬编码演示数字。标题、BV、时间和长错误提示都要验证截断、换行和完整内容的查看方式。窄屏仅表格与必要图表区域可以横向滚动，整个面板不能横向溢出。

#### 设置页

按“播放与提示”“页面标记”“标签样式”“诊断与维护”分组，使用标题、短说明、分隔线和设置行组织信息。开关采用带可访问名称的原生 checkbox 语义与自定义轨道；位置使用四角选择控件；透明度保留滑块和数字输入联动；阈值配内联错误和对应颜色示意。

桌面右侧安排宽约 260 px 的样式预览，可切换已访问、低/中/高进度、多 P 示例；窄屏移到标签样式下方。用脚本自有的中性视频画幅和文字生成预览，不请求真实封面。预览函数接收草稿配置，不能临时改全局 CONFIG，也不能进入真实历史存储或页面扫描队列。

设置实例分别持有已保存快照、草稿和 dirty 状态。切页签不重置草稿；保存验证通过后才写入设置并触发实际标记刷新；恢复默认进入草稿，保存后生效。保存期间禁用重复提交，失败保留草稿。底部状态使用明确中文，如“有未保存的修改”“正在保存”“已保存”。

离开有修改的面板时显示保存后关闭、放弃修改、继续编辑三个动作；普通关闭不额外确认。外部记录更新不重建设置控件，也不覆盖正在输入的草稿。

#### 历史管理页

搜索独占主要宽度，清除入口可直接触达；状态与排序在次级工具行。导入导出作为数据操作，保留周期清理收纳在明确标识的数据维护区域，避免与常用筛选混在同一行。

记录列表保留标题、key、状态、进度、时间和删除能力：标题为主信息，key 为次信息；进度用小条和数值共同表示；状态使用带文字的浅色标识。桌面表头固定，默认每页仍为 20 条，支持现有 30/50/100 选项。

出现选择时显示批量操作条，说明总选中数量与“当前页全选”的范围；保留跨页选择，清理失效 key，单个选择变化即时更新全选/部分选中状态。空历史提供导入或开始观看的说明；无匹配结果提供清除条件；加载、错误和空列表必须分开呈现。

#### 统计页

主要数字先展示总记录、已观看、已访问和近七天记录，进度分布作为次层信息。统一重画现有 SVG 图表：高进度占比环、状态/进度条形图、近期趋势；保留原有数据和范围能力，提供文字值与图形说明。

“近期记录趋势”注明按最近保存时间统计；高进度占比的分母仍为全部记录。与阈值相关的数字采用能准确解释现有公式的标签，避免把高进度比例等同于真实完播率或累计观看次数。

### 7. 面板组件与生命周期

在同一脚本内部将管理功能拆成小型面板控制器与设置、历史、统计渲染职责；`UIComponent.showManagerPanel()` 保留入口委托，业务操作继续走存储与设置接口。组件采用事件委托、局部更新和明确 dispose，不引入 React、Vue 或打包输出。

面板和公共组件使用限定根节点的 `--bvh-*` 变量与选择器，局部设置 box-sizing、字体和控件外观；不修改 Bilibili 的全局 button、input、a 等样式。保持现有延后 DOM 启动策略，避免重新引入头部挂载干扰。

公共确认弹窗使用统一面板组件替代保留周期清理的原生确认外观，信息内容和取消行为保持原规范。Toast 分为信息/成功/失败，进度反馈明确已处理数量；撤销提供真正的按钮。提交过程中退出面板仅解除界面订阅，不把已开始的可靠提交误标为取消；可取消的查询、预览与等待任务则随面板终止。

使用顶层弹窗栈管理焦点和 Escape。打开时保存触发入口，焦点移到标题或首个控件；Tab 限制在顶层弹窗；关闭内层确认返回原控件，关闭主面板返回入口。遮罩只关闭其对应层，并经过草稿关闭规则；滚动锁保存和恢复原样式，避免覆盖站点已有值。状态反馈使用 aria-live，错误关联到输入，图标按钮有中文名称，页签提供选中与键盘语义。

### 8. 验证方法与完成标准

验证工具放在 `tools/bilibili-history/`，直接加载目标脚本中的实现或通过仅测试时注入的导出方式访问，不复制业务算法制造自证测试。使用内存 GM、可控媒体事件、假时钟和延迟/失败注入覆盖数据与会话；使用已安装 Playwright 加载本地合成页面并注入原脚本。

| 验证层 | 必须覆盖的证据 |
| --- | --- |
| 存储与索引 | 八组基线问题的相关复现、两个实例及不同子域的共享存储模型、交错提交、提交信号遗漏、批次中断、并发整理、旧备份与删除、索引未命中零写入 |
| 播放与续播 | URL 先变、媒体先变、快速切 P、同元素换媒体、媒体重建、首次超时后恢复、销毁后旧回调 |
| 显示与生命周期 | 关闭进度条、阈值/位置/透明度更新、多 P tooltip 更新、无关卡片不重建、面板开关 20 次后订阅归零 |
| 查询与统计 | 0、少量、10000 条合成数据，重复翻页零全量重算、过期搜索丢弃、删除中查询、7/30/90 天统计一致 |
| 视觉与交互 | 1440×900、1024×768、390×844，三个页签、草稿、校验错误、空状态、批量选择、清理确认、进度/失败/撤销、键盘、200% 缩放、减少动态效果 |
| 真实页面 | 现有首页/搜索/历史/视频/分 P/合集/播放列表/头部弹窗适配及悬浮隐藏规则；使用测试数据时不混入用户真实历史 |

截图必须打开检查并修正溢出、遮挡、焦点不可见、文字对比不足、长标题和危险操作层级等问题，不能只依靠截图文件存在判定通过。真实页面不可访问时要记录缺失项，不把合成夹具结果表述成线上验证。

## Risks / Trade-offs

- [独立提交增加持久化元数据] → 先完成带故障注入的协议与检查点测试，再接入业务；整理只删除已被确认替代的副本，报告操作数量与字节趋势。
- [存储 API 返回与页面退出竞态] → 异步提交确认、唯一事务身份和原采样备份共同处理；生命周期结束不伪报成功。
- [旧页面继续运行旧版写法] → 升级时保留旧数据并提示刷新旧页面；新旧写入协议并发不列为已支持状态。
- [播放身份依赖站点 DOM] → 保留现有稳定解析和低频自愈，增加身份切换隔离；不同页面类型以真实站点回归确认。
- [界面重构范围较大] → 先打通共用面板与设置草稿，再迁移历史、统计和反馈，逐阶段跑行为与视觉回归。
- [本机字体与窄屏渲染差异] → 使用明确本地回退字体栈，三个尺寸、长中文标题和页面缩放共同验收，不依赖远程资源。
- [查询时间受数据量和扩展实现影响] → 同时记录操作次数与时间，脚本计算分段和缓存复用为硬验收，扩展读写延迟单列，避免用演示数据掩盖瓶颈。

## Migration Plan

1. 实现前用兼容导出和合成 v1/v2/v3 数据建立恢复与升级夹具；保留当前脚本版本的可回退代码，不自动创建提交。
2. 先增加存储适配、不可变提交、读取合并和故障测试；新写入协议未验证通过前不接管真实用户历史。
3. 首次启用时登记新协议，继续读取旧分片；以完整数据重建带覆盖信息的派生索引。中断后重复初始化不得重复导入或清空旧数据。
4. 依次接入备份/导入/删除/同步、播放会话、标记更新、查询缓存，再接入新管理面板。
5. 回退到旧协议前应停止其他页面写入，导出并校验当前有效历史，通过经测试的恢复流程生成旧版可读的完整 v3 分片快照；不得仅依赖旧版“跳过已有记录”的普通导入更新旧进度，也不得直接删除新操作区。
6. 当前开发任务不变更脚本版本或仓库说明文档；用户明确要求收尾时再统一判断版本递增、README/CHANGELOG 和实际 GM API 授权，说明新旧页面及回退限制。
