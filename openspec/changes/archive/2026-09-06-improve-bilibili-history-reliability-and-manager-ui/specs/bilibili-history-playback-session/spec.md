## Purpose

确保页面路由、分 P 选择、播放器元素和视频元数据发生变化时，观看进度始终归属于正确的视频会话，并让延迟加载、媒体重建和续播操作不会把旧页面的数据写入新视频。

## ADDED Requirements

### Requirement: 访问与标题记录不依赖播放
系统 MUST 在新视频会话建立后记录访问；标题尚未就绪时允许暂缺，身份确认后的页面标题 MUST 在不播放时也能补全。

#### Scenario: 快速换集后暂停停留
- **WHEN** 用户切换分 P、合集或播放列表视频后未开始播放
- **THEN** 新视频 MUST 有访问记录，页面标题就绪后 MUST 自动补全空标题
- **AND** 补标题 MUST 保持已有状态、进度和最近保存时间，不得恢复已删除记录或使用旧视频标题


### Requirement: 进度绑定已确认的视频身份
系统 MUST 将每次进度采样与已确认的视频 key、标题和媒体实例关联；身份尚不一致时不得把当前媒体进度保存到新视频 key。

#### Scenario: URL 先变而媒体尚未切换
- **WHEN** URL 已从视频 A 切到 B，但播放器仍显示 A 的媒体与进度
- **THEN** 系统 MUST 不得将 A 的进度或标题写入 B
- **AND** B 的播放进度 MUST 等到其媒体身份确认后才开始更新，独立的访问状态记录不受此限制

#### Scenario: 快速连续切 P
- **WHEN** 用户连续从 P1 切到 P2 再切到 P3，旧媒体事件或异步任务随后到达
- **THEN** 各次采样 MUST 只影响其所属分 P，最终活动会话 MUST 对应 P3

### Requirement: 结束会话使用最后有效快照
系统 MUST 在会话结束时保存属于该会话的最后有效进度，且结束后的回调不得再次绑定媒体或更改其他会话。

#### Scenario: 切换时旧元素已装载新媒体
- **WHEN** 旧会话结束时，其原媒体元素已经承载另一个视频
- **THEN** 系统 MUST 使用旧会话缓存的有效快照完成收尾，而不是读取已经改变的媒体进度

### Requirement: 媒体重建与延迟加载可以恢复监听
系统 SHALL 在同一活动会话内恢复被替换或延迟出现的媒体监听，并避免重复绑定和重复保存。

#### Scenario: 播放器重建媒体元素
- **WHEN** 当前视频没有切换，但播放器重建了媒体元素
- **THEN** 系统 MUST 解除旧元素监听并绑定新元素，后续有效进度 MUST 继续记录

#### Scenario: 首次媒体等待超时后出现
- **WHEN** 首次等待媒体超时，但当前视频会话仍然有效且媒体稍后出现
- **THEN** 系统 MUST 能恢复监听，并且不得无限叠加观察器或定时器

### Requirement: 续播任务遵守会话生命周期
系统 MUST 仅在续播目标仍对应当前有效会话时执行跳转，并在会话被替换时取消其未执行的续播任务与提示。

#### Scenario: 元数据等待期间切换视频
- **WHEN** 系统正在等待目标视频元数据以执行续播，用户先切换到另一个视频
- **THEN** 原续播任务 MUST 不得跳转或播放新视频，原提示 MUST 不再触发旧操作
