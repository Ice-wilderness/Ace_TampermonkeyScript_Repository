## Purpose

让历史记录数量增长后，搜索、筛选、排序、分页和统计仍保持可操作性，并通过稳定的数据版本和过期结果处理确保异步计算不会覆盖用户的新输入或呈现过时结果。

## ADDED Requirements

### Requirement: 视频按需读取与自动后台整理
系统 MUST 按需加载当前视频及关联分 P，并自动后台整理旧数据；用户无需打开历史管理触发整理，前台进度保存 MUST 不等待后台整理完成。

#### Scenario: 未打开管理面板的普通访问
- **WHEN** 用户升级后访问视频且旧数据尚需整理
- **THEN** 系统 MUST 自动安排后台整理，完成后持久保存结果，后续访问不重复读取无关历史数据块
- **AND** 首次旧批次的完整校验允许继续进行，但 MUST 显示真实等待状态

#### Scenario: 整理过程中关闭页面
- **WHEN** 整理已完成部分数据组后页面关闭
- **THEN** 下次访问 MUST 校验并复用仍有效的已完成组，继续处理其余数据，不丢失历史或删除状态


### Requirement: 历史分页复用同一查询结果
系统 MUST 在数据和查询条件未变化时复用已有过滤与排序结果，翻页、选中记录及切换每页数量不得重新读取并排序全部历史。

#### Scenario: 大量记录下连续翻页
- **WHEN** 合成数据包含 10000 条合法历史，用户在相同过滤和排序条件下连续翻页
- **THEN** 每页 MUST 展示正确的对应记录，且不得重复执行全量历史读取和排序

### Requirement: 数据准备期间界面保持可操作
系统 SHALL 先提供可操作的面板框架和加载反馈，再完成大量数据的查询或统计；处理期间用户 MUST 能输入、切换页签和关闭面板。

#### Scenario: 冷启动打开大量历史
- **WHEN** 用户首次打开包含 10000 条合成记录的管理面板
- **THEN** 搜索和关闭控件 MUST 在全量结果完成前可操作
- **AND** 系统 MUST 显示真实加载状态，不得用空数据结果代替尚未完成的查询

### Requirement: 过期查询结果不覆盖新状态
系统 MUST 只呈现与当前数据版本、搜索条件和活动面板一致的查询结果。

#### Scenario: 搜索 A 尚未完成又搜索 B
- **WHEN** 用户输入搜索 A 后立即改为 B，而 A 的计算较晚返回
- **THEN** 结果列表 MUST 对应 B，搜索框 MUST 保持焦点和用户输入

#### Scenario: 查询期间数据发生变化
- **WHEN** 查询进行期间发生删除、导入、恢复或远程记录更新
- **THEN** 最终显示结果 MUST 对应最新有效数据，旧计算结果不得覆盖它

### Requirement: 统计复用数据并保持既有口径
系统 SHALL 复用同一数据版本下的统计输入，切换已有 7、30、90 天范围时正确更新图表，并保留既有统计计算口径。

#### Scenario: 重复查看相同统计范围
- **WHEN** 数据和阈值未变化，用户重复查看同一统计范围
- **THEN** 系统 MUST 复用已有计算结果，数字与图表 MUST 一致

#### Scenario: 统计图表解释其时间含义
- **WHEN** 统计页展示近期趋势或高进度比例
- **THEN** 界面 MUST 明确这些数据来自记录的最近保存时间及进度阈值，不得表述为累计观看时长或逐次观看次数
