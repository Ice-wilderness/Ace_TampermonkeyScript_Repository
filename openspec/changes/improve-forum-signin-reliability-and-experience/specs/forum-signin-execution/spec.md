## Purpose

为控制台直签和站点页面签到提供一致的任务生命周期，使重复操作、网络异常与人工等待都有明确的处理边界。保留各站立即并行执行、轮流激活标签继续签到的使用方式，通过目标防重、可恢复状态及页面关联减少重复请求和错误关闭页面。

## ADDED Requirements

### Requirement: 同一目标的在途任务防重

同一控制台实例 MUST 对同日同一目标的单行操作和批量操作统一防重；执行中及已有有效页面任务的目标 MUST NOT 因重复批量点击启动第二个任务。

#### Scenario: 执行中再次点击批量直签
- **WHEN** 一个目标正在直签而用户再次点击批量直签或该行直签
- **THEN** 控制台 MUST 复用已有任务并保持一次执行
- **AND** 尚未启动的其他目标 MUST 立即独立执行

#### Scenario: 另一控制台已有有效任务
- **WHEN** 控制台发现同日同一目标由其他实例持有尚未过期的执行记录
- **THEN** 控制台 MUST 展示正在其他页面处理并暂缓启动
- **AND** MUST 在记录过期后提供先检查结果再恢复的入口

### Requirement: 直签任务立即并行

批量直签 MUST 立即并行启动各个可执行目标，并为每个目标独立保存进度和结果；MUST NOT 设置跨站执行名额或等待队列。单个站点失败、超时或人工阻塞 MUST NOT 阻止其他目标完成。

#### Scenario: 多个直签目标同时待处理
- **WHEN** 多个可执行直签目标同时待处理
- **THEN** 各目标 MUST 立即开始执行
- **AND** MUST NOT 等待其他站点释放名额

#### Scenario: 一个目标请求超时
- **WHEN** 批量直签中的单个目标超时
- **THEN** 其他目标 MUST 能继续执行并更新自己的最终状态

### Requirement: 请求具有明确超时

脚本自身的跨站请求和页面内请求 MUST 具有明确的有限超时；超时 MUST 结束该次请求等待并产生可读原因，同时释放该请求相关的计时器和执行资源。

#### Scenario: 请求长时间不返回
- **WHEN** 请求在配置的期限内未完成
- **THEN** 该次等待 MUST 以超时结果结束
- **AND** 控制台 MUST 显示重试、检查结果或人工处理等适用操作

### Requirement: 按失败类别进行有限恢复

脚本 MUST 区分临时网络或服务异常、未登录、人工验证、适配失效和提交结果未知；只有可安全重试的临时异常允许自动有限重试，其他情况 MUST 停止自动重复提交并给出下一步操作。

#### Scenario: 未登录或需要验证码
- **WHEN** 站点明确要求登录或完成人工验证码
- **THEN** 脚本 MUST 停止自动重试并保留对应人工待办

#### Scenario: 临时服务错误
- **WHEN** 检查请求遇到可重试的临时网络或服务错误
- **THEN** 脚本 MUST 在有限次数内逐步延长等待后重试
- **AND** MUST 展示当前尝试次数和等待时间

#### Scenario: 站点结构不再识别
- **WHEN** 脚本等待页面就绪后仍找不到必要入口或响应结构
- **THEN** 脚本 MUST 提示适配可能失效并保留诊断
- **AND** MUST NOT 无限刷新页面或重复提交

### Requirement: 有效页面任务避免重复打开

控制台 MUST 跟踪本次打开的站点任务；重复批量处理时 MUST 复用尚未结束的页面任务，页面已关闭或任务失效时 MUST 提供重新打开与结果检查操作。

#### Scenario: 验证码页面已经打开
- **WHEN** 用户再次批量处理一个已有有效验证码页面的目标
- **THEN** 控制台 MUST NOT 再创建相同目标的标签页
- **AND** MUST 提供查看该任务或继续人工处理的入口

#### Scenario: 浏览器拒绝打开页面
- **WHEN** 页面打开操作失败或浏览器拒绝请求
- **THEN** 控制台 MUST 提示打开失败
- **AND** MUST NOT 继续把该目标显示为已成功打开

### Requirement: 前台任务独立打开

批量操作 MUST 立即为需要前台处理的各站点独立打开标签页，MUST NOT 设置前台队列或依赖用户点击“继续下一项”。用户轮流激活各标签时，原有站点签到流程 MUST 能继续执行。

#### Scenario: 多个站点都需要前台
- **WHEN** 批量处理包含 SS同盟、2dfan、老王或其他前台目标
- **THEN** 控制台 MUST 立即打开各站独立标签
- **AND** 某站需要验证码或等待页面就绪时 MUST NOT 阻塞其他站点

#### Scenario: 升级前残留排队记录
- **WHEN** 旧版本为未启动目标保存了排队状态和执行记录
- **THEN** 新版本 MUST 解除旧排队并恢复该目标的可执行状态
- **AND** MUST NOT 让旧队列继续阻塞打开或执行

### Requirement: 自动关闭对应本次已确认任务

启用自动关闭后，脚本 MUST 仅关闭已确认自动成功且能够关联到本次签到动作或控制台打开任务的页面；人工标记成功、任务不明及站点其他浏览页面 MUST NOT 触发任务自动关闭。

#### Scenario: 同站点另一个普通浏览页
- **WHEN** 一个签到任务完成，而同站点另一个标签页正在普通浏览
- **THEN** 脚本 MUST 仅关闭可关联到该任务的页面
- **AND** MUST NOT 使用站点级共享待关闭标记关闭其他页面

#### Scenario: 页面关闭受限
- **WHEN** 浏览器不允许脚本关闭已经完成的任务页面
- **THEN** 脚本 MUST 保留成功状态并提示可以手动关闭

### Requirement: 过期任务可恢复且不会永远执行中

执行记录 MUST 有有效期限；页面刷新、异常退出或跨日后遗留的任务 MUST 转为可恢复状态，并在重新执行签到动作前先检查是否已经完成。

#### Scenario: 页面退出后遗留执行状态
- **WHEN** 任务长期没有进度且所属页面已经失效或记录过期
- **THEN** 控制台 MUST 提供重新检查和恢复入口
- **AND** MUST NOT 永久禁用该目标的操作

#### Scenario: 普通页面继续未完成流程
- **WHEN** 用户普通打开或刷新站点，旧记录为结果未知、已打开或验证前入口点击
- **THEN** 脚本 MUST 继续站点自身的检查及后续签到流程
- **AND** MUST NOT 将其隐式转换为只读检查
- **AND** 显式重新检查及已实际提交的ZodGame表单 MUST 仍避免重复提交
- **AND** SS同盟普通页面 MUST 执行独立新逻辑，不受旧未知状态、成功缓存及泛用动作记录的隐式拦截；新逻辑真实提交后的本标签记录 MUST 防止重复发帖

#### Scenario: 昨日任务在今日返回
- **WHEN** 昨日启动的任务在今日返回结果
- **THEN** 脚本 MUST 根据证据所属日期保存结果
- **AND** MUST NOT 将缺乏今日证据的昨日结果直接记作今日成功
