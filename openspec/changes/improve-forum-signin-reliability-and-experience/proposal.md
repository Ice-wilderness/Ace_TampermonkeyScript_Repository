# 论坛签到可靠性与使用体验优化方案

## Why

当前签到脚本已支持 17 个站点，其中 6 个支持控制台直签，但部分适配把点击或提交当作成功，重复批量操作会重新执行任务，控制台刷新也可能打断搜索和配置编辑。需要把结果确认、任务调度、状态恢复和界面更新作为一次完整改进，降低漏签、重复提交与日常操作负担。

## What Changes

- 统一保守的成功判定，优先修复月曦、ZodGame、初音的青葱和 SS同盟；结果未知时保持待确认，禁止提前写入成功日期和触发成功自动关闭。
- 分离状态检查与签到动作；增加任务防重和标签页复用；各站立即并行启动，保留轮流激活前台标签即可继续签到的原有方式，不增加排队。
- 按网络异常、未登录、验证码、站点适配失效和结果未知分类恢复；统一请求超时和有限重试，提交后优先复查。
- 修复输入事件捕获拦截和样式重复注入；改为局部更新，保留中文输入、焦点、滚动位置和配置草稿，异步任务不重新打开已关闭的控制台。
- 增加跨标签页状态监听、切回页面刷新和跨日刷新；重新组织人工待办、自动处理中、失败及完成分组，使用状态相关的主要操作。
- 增加今日状态重置、重新检测、手动标记来源及短时撤销，同步处理控制台状态和旧成功日期。
- 增加历史保留期限与清理、配置及可恢复状态备份导入导出，兼容已有 GM key 和历史数据。
- 增加单站点失败诊断入口，完善 nonce 等字段的脱敏；只展示脚本自身已有请求诊断，不增加网页全量抓包或 API 探测。

## Capabilities

### New Capabilities

- `forum-signin-verification`：按当前用户和当日证据确认签到，区分提交与完成，保留人工验证码边界。
- `forum-signin-execution`：任务生命周期、防重、有限重试、请求超时与独立页面任务，不加入执行队列。
- `forum-signin-storage`：兼容存储、手动恢复、撤销、历史清理和备份恢复。
- `forum-signin-diagnostics`：脚本自身失败记录的单站点展示、分类和脱敏导出。

### Modified Capabilities

- `forum-signin-dashboard`：调整状态展示和批量打开语义，增加局部刷新、持续同步、操作恢复及配置备份入口，同时保留 Limestart 控制台范围与既有站点功能。

## Impact

- 实现目标仅为 `scripts/自用论坛辅助签到自写.js`，涉及站点适配、公共请求、GM 状态、调度、页面关闭和控制台 UI；不修改其他用户脚本或 API 探测工具。
- 验证沿用项目已有 Node.js、`node:vm` 和 Playwright 开发依赖，按需新增 `tools/forum-signin/` 的轻量回归检查，不引入运行时框架。
- 实现时补齐状态监听、存储枚举和清理所需的 GM 权限；不扩大站点匹配和跨域访问范围，不增加云服务或凭据备份。
- 保留既有成功日期、设置和自定义目标；新字段采用增量兼容读取。完整历史按用户配置保留，最近成功日期不随历史清理删除。
- 实施范围包括目标脚本及轻量回归工具；按用户提交要求收尾为2.20.0，同步更新对应README分区和CHANGELOG版本记录。
- 现有规范要求未完成目标全部打开，本方案明确排除在途任务，其余前台目标立即独立打开；保留轮流激活标签继续签到的方式，不排队。运行时失败诊断不改变 `forum-signin-api-discovery` 的开发工具边界。
