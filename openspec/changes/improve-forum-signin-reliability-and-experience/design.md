# 论坛签到可靠性与使用体验技术设计

## Context

动机和完整范围见 `proposal.md`。目标脚本当前为单文件异步 IIFE，版本 `2.19.0`，包含 17 个站点配置、6 个直签适配，以及 Limestart 控制台和站点页提示。继续沿用单文件发布方式，不迁移到前端框架。

已确认的实现约束：

- `BBSSignHelperData` 与按站点拆分的成功日期并存；每日状态同时写入汇总对象及按日期、站点拆分的 key。拆分值已有读取优先级，升级应在此基础上改进。
- `runDirectTargets` 全量并发，筛选只排除成功和跳过；页面复查反复调用完整 `site.run()`；没有统一任务生命周期。
- `gmRequest` 定义超时回调但不传入超时，页面请求也没有统一超时；直签对所有失败统一三次重试。
- 控制台用 `showDashboard` 全量重建，输入捕获监听会阻断目标事件；样式检查的 ID 未赋给插入节点。
- 现有 Node.js 与 Playwright 开发依赖可用于轻量回归；签到脚本尚没有专用回归入口。`tools/signin-api-discovery/` 是独立开发工具，不进入修改范围。
- 现有 dashboard 规范会被本变更的 delta 明确更新；API 探测规范保持不变。源码中仍可用的验证码、GBK 解码及登录访问流程必须保留。

## Goals / Non-Goals

**目标：** 将站点专属证据、任务调度、目标状态和界面展示分层，通过一套可恢复的状态变化约定处理所有既有站点；保持安装形态、已有数据与站点范围兼容。

**非目标：** 新增站点、自动解验证码、多账号管理、云同步、网页全量抓包、自动探测接口、全面重写脚本或修改其他用户脚本。普通访问时的既有自动签到入口保留；本次不新增全局接管导航功能。

## Decisions

### 1. 站点适配返回结构化结果，成功记录统一提交

将站点适配逐步收敛为 `check(context)` 和 `execute(context)` 两类能力：前者读取页面或状态接口，不产生签到动作；后者只在已知需要签到时执行一次动作，再进入检查。保留站点特有的查帖、跳转、验证码监视等步骤，但返回明确阶段和结果。

结果携带 `outcome`、`reasonCode`、`message`、`evidence`、`submitted` 和可识别的 `evidenceDate`。内部 outcome 覆盖完成、未完成、等待结果、需登录、需验证、临时异常和适配失效；外部仍兼容已有 status 值，并增加结果未知的显示映射；旧排队记录只作兼容读取，不再生成新排队任务。`submitted=true` 之后的请求超时归为结果未知，不能直接进入再次提交。

统一完成入口只有在证据有效且任务未被重置时才写成功日期、记录自动来源并评估自动关闭。保留已有自动成功记录读取，将来源标为 `legacy`，不把历史记录批量判成无效。

优先修复并添加反例验证：

| 站点 | 确认依据 | 明确排除 |
| --- | --- | --- |
| 月曦 | 本人签到操作区的完成状态或明确提交响应 | 仅点击按钮 |
| ZodGame | 提交结果或后续签到页确认 | 找不到表单、仅调用 submit |
| 初音的青葱 | 寻宝专属结果区域的完成或已完成提示 | 无提示、无异常、无关“成功”通知 |
| SS同盟 | 本人已发布评论的当日时间或日期内容；利用已有作者过滤查询其他分页 | 编辑器草稿、其他用户评论、仅点击提交及旧成功缓存 |

其余 13 个站点逐个检查证据范围及是否会在复查时产生动作；保留次元狗状态复查、有叽叽防重复提交和 GBK 解码。SS同盟按用户最新要求基于真实页面独立重写：定位`data-role="replyArea"`及其回复表单，等待CKEditor实例ready，使用异步`setData`回调、`change`和`updateElement`同步`topic_comment_*`隐藏字段，再点击该表单可见且可用的按钮。没有CKEditor API时保留关联表单内的DOM/iframe降级；就绪失败最多刷新3次，不添加跨站队列。

本人结果检查优先当前DOM，否则基于页面已有`view_author`入口向本站发送一次本人过滤GET，不遍历其他人的几十页评论。新提交记录仅写当前标签sessionStorage，按日期、帖子和账号关联，点击可用回复按钮后未确认的任务只检查结果；确认成功清除记录。旧泛用动作标记及成功缓存不能跳过新流程，SS同盟也不再叠加主引擎90秒结果轮询。

选择显式适配边界而非继续扩大通用正则，是因为不同页面的排行榜、提示说明与真实用户状态含义不同。明确成功响应可以直接确认，不强制每个站点额外发送第二次请求。

### 2. 一套调度同时覆盖单行与批量操作

按目标维护任务，使用随机 `taskId`、`ownerId`、启动日期、阶段、更新时间、有效期和当前操作代次。单行、批量、重试都经过同一个调度入口；同实例先登记在途任务，再异步执行，避免两次点击之间出现启动窗口。

各站直签立即并行启动，不设置跨站并发名额或等待队列；仍对同一目标复用在途任务。所有分支使用 finally 释放本目标的资源。

共享目标任务记录采用有限租约、启动前复读和任务标识校验；检测到其他控制台有效任务时不启动。建议初始租约 30 秒、活跃任务每 10 秒续约，人工页面任务有效期 10 分钟；恢复时继续站点自身的完成检查及后续流程，不能仅因租约过期重复已提交的表单。

页面任务的只读意图由 `checkOnlySource` 区分显式重新检查与人工状态检查，兼容旧记录时解除无来源的隐式只读标记。普通打开、旧结果未知和验证前入口点击不能把页面锁为只检查；老王跳转后继续监听人工验证并自动提交，青葱继续原有寻宝动作。ZodGame实际已提交的表单仍走只读确认；SS同盟由独立新提交记录管理待确认，不由旧未知状态及动作记录强制只读。

GM 存储没有通用原子比较交换，不能把共享租约宣称为跨所有来源的绝对互斥。它负责跨页协调，同实例 Map 提供确定防重；有状态检查和幂等语义的站点再由提交前检查减少跨实例竞争。极端竞争或非幂等动作结果未知时停止自动重提。相关限制须在验证记录中明确。

状态示意：

```text
not-started ------------> running --> verifying --> success
                              |            |
                              v            v
                        needs-login   result-unknown
                              |
                              v
                       needs-foreground

temporary-error --> retry-wait --> checking --> running
reset/expired   --> checking --> ready-or-manual
```

### 3. 超时和错误分类先于自动重试

`gmRequest` 显式传入默认 20 秒的 timeout，保留管理器错误与超时分类，补充取消处理；页面 fetch 使用可取消的超时控制。请求计时覆盖需要读取的响应体，不能只限制收到响应头前的时间。若页面域与沙箱的 AbortSignal 不兼容，使用同执行域的控制器；降级至少结束等待并拒绝迟到结果，不声称底层请求已取消。

重试最多 3 次，建议间隔 3 秒、6 秒，支持合理范围内的服务端 Retry-After。未登录、验证码、适配失效不重试；429 及临时服务异常分类显示，不全都归为登录失效。HTTP 状态、最终 URL、响应类型与站点业务结果共同判断，保留各站必要的文本和字符集处理。

只对可安全重复的检查和已知未提交动作自动重试。已提交且回包丢失时执行有界的 `check`；没有证据证明未执行就保持结果未知。替代当前通用 `waitForSiteSuccessRecheck` 对整段 run 的重复调用，避免重复发帖和奖励请求。

### 4. 页面任务与关闭范围绑定到具体任务

控制台跟踪本次 `GM_openInTab` 返回的句柄、目标、任务 ID 与打开时间，独立于自动关闭选项保存打开任务；有效任务不重复开页。不能依赖站点名判断某个标签是否属于签到任务。

对需要跨跳转保留关联的页面，控制台在支持的目标 URL 中附加专用非敏感任务参数，站点脚本验证其与共享任务一致后，在该页面的 sessionStorage 保存关联。参数只用于本脚本任务识别，不作为成功或登录依据；只移除本参数，且不破坏站点路由或已有参数。页面内主动发起的签到动作也创建本页面的任务关联。

登录跨域跳转、站点不接受附加参数或管理器不返回可跟踪句柄时，降级为显示状态及手动检查；有可靠控制台句柄时可由控制台关闭该句柄。不能可靠关联时不自动关闭，不能重新使用现有站点级 pending 标记让任意同站点页面认领。

自动关闭只响应本任务的自动确认，手动标记成功不关闭页面。失败时保留成功记录并展示手动关闭提示。既有自动关闭偏好继续生效，关闭前重新核对任务仍有效。

前台目标在批量操作时各自立即打开标签页，不等待其他站点完成，不增加“继续下一项”或“暂缓”队列操作。用户轮流激活标签即可让原有站点流程继续；验证码仍由用户在对应页面完成。旧版本尚未启动的排队状态释放执行记录并恢复可执行，避免升级后继续受旧队列阻塞。无法可靠激活已有标签时显示已有任务和站点入口，不冒称已切到原标签。

### 5. 目标状态为权威记录，兼容旧成功日期

沿用按日期、目标拆分的状态 key 作为权威记录，补充可选字段 `schemaVersion`、`confirmationSource`、`taskId`、`mutationId`、`reasonCode` 和证据摘要。旧字段继续可读；未知新字段不应导致整条旧记录不可用。

读取优先级为有效的目标级状态及人工操作代次、站点拆分成功日期、旧汇总回退。旧汇总仍作为兼容镜像，不能用过期快照反向覆盖拆分记录。写入入口统一，异步回调提交前比对当前 taskId 和 mutationId，重置后迟到结果不得复活已撤销记录。

重置或由成功改为失败、跳过时，仅撤销今日成功值；使用明确的空值覆盖拆分 key 并更新旧汇总，避免删除拆分值后旧汇总成功重新回流。可识别的其他日期历史和最近有效历史成功保留。站点引擎启动也读取权威状态，不能继续仅凭旧日期跳过。手动跳过与手动失败按当日人工状态处理，显式重新检测可以解除该状态进入检查。

手动标记成功仍兼容写入日期，但来源为 `manual`；旧记录为 `legacy`，自动证据为 `automatic`。来源直接显示，批量成功仅作用于用户明确选择的可人工确认目标，排除正在执行目标。

### 6. 撤销与导入使用有边界的恢复快照

人工操作记录每个目标的操作前值与操作后 mutationId，默认撤销窗口 10 秒。撤销只恢复仍处于对应操作版本的目标，站点刚产生新结果时不覆盖，批量撤销报告实际恢复数量。页面刷新后不承诺继续保留短时撤销入口。

备份使用带类型、schemaVersion、导出时间和数据分区的 JSON；默认只导出配置，可选包含成功日期及每日状态。不得导出请求日志、凭据、页面对象、租约、pending 关闭记录或撤销计时器。

导入先解析并限制体积（初始 5 MiB）、数组规模、网址协议、枚举值、ID 唯一性和日期有效性，再显示新增、更新及替换范围预览。首版采用明确的分区替换：仅替换文件中已选择且存在的数据分区，不隐式清空未导入分区；不增加含糊的自动合并规则。

应用前保存一份受容量约束的本脚本恢复快照与导入事务标记，失败后尝试逐分区回滚；启动发现未完成事务时先恢复并提示结果。GM 多 key 写入不具备原子性，不能宣称绝对事务保证；回滚失败时保留快照下载及重试恢复入口。仅在成功后清除事务标记，保留最近一次可恢复快照。

历史日期原样恢复，排队、执行中、已打开等瞬态记录归一为待检查；不恢复执行权或自动关闭关联，也不在导入结束后自动发起签到请求。首版没有既有脚本导出格式，因此兼容要求针对现有 GM 数据和本方案产生的已支持备份版本，不猜测其他工具的未知 JSON。

### 7. 历史清理有开关、预览和完整的 key 范围

新增历史保留选项：保留全部、7 天、30 天、90 天。升级默认保留全部，避免新版本静默删除既有历史；用户选定有限保留期后可启用每日一次的过期清理，并提供手动预览入口。这里清理的是每日详细状态，不删除最近成功日期、配置、当日数据和有效任务。

仅清理已知本脚本日期 key 前缀和旧汇总中的对应日期，不扫描或删除其他脚本数据；按已知 key 索引及必要的 GM 枚举完成清理，避免每次重绘枚举存储。清理小批进行，失败可重试且不会清掉今天。

首次迁移保留旧汇总可回退读取；首次实际清理前提供历史备份入口和清理范围。清理是用户选定保留策略后的预期结果，不能在后续升级把被清理历史从兼容镜像恢复出来。

### 8. 控制台保持挂载，数据更新不等同于打开面板

区分显式 `openDashboard`、视图导航与已挂载视图更新。异步回调只更新状态仓库、入口徽标和当前相关行，不调用带打开行为的 show 函数。关闭后的任务可以继续完成，不重新弹出面板；现有可选三秒提醒不因本次后台任务变化再次打开已关闭面板，直到新的显式操作或新一天。

按 targetId 复用行节点，更新文案、徽标和按钮；视图切换才创建对应内容，配置草稿单独保存在内存视图状态。搜索控件始终保留，组合输入期间不筛选，compositionend 后统一筛选。事件隔离在控件自身或面板冒泡阶段完成，不能在祖先捕获阶段阻止目标事件。

样式函数创建一次带稳定 ID 的节点，监听注册也保持幂等。滚动、焦点和折叠状态不随任务变化丢失，正在操作的行需要移动分组时延后到交互结束。继续保留窄屏适配、现有提示抑制和已签到提示次数限制。

分组映射：人工待办包含需登录、需验证码及其他人工条件；自动处理中包含执行、重试等待、有效页面任务和复查；失败待处理包含最终失败、适配失效及结果未知；已完成包括自动或人工成功，并独立显示跳过数量。未开始目标保留单独待启动区及统计，避免漏掉原有功能。

### 9. 值变更监听与生命周期刷新取代展示倒计时依赖

Limestart 监听已启用目标当日状态及成功日期变化，配置变更后重建所需监听，移除不再使用的监听。跨页通知合并到一个轻量更新批次；多个回调不反复重建 DOM。

显式展开、window focus、visibilitychange 恢复可见时补读状态。本地午夜按当前时间重新计算日期，重绑当日 key 并清理昨日展示上下文；休眠恢复同样核对日期。日期规则继续采用用户本地日历日，不在本次改成站点时区配置。

监听能力缺失时，仅在面板可见或存在有效任务时每 5 秒检查，隐藏且无任务时停止轮询；回到可见页面立即补读。统一资源注册与释放，不能给每个目标各加一个无限轮询。原两分钟倒计时可移除或只作为显示，不再决定结果同步有效期。

### 10. 诊断使用显式任务上下文和统一脱敏

每次请求显式传递对应任务/尝试的 debugContext，避免并发任务依赖全局 `activeSignDebugContext` 导致记录串站。保留原三天、80 会话、每会话 50 条及文本截断上限。

脱敏规则集中包含 nonce 和 `_nonce`，覆盖结构化 URL、头、JSON、表单及可识别 HTML 验证字段；先脱敏再截断和存储，读取历史日志时再次脱敏。文本证据摘要和异常 message 也经过同一路径，不持久化原始凭据。

单站点诊断视图只读取自己的近期记录，允许导出该站点；无请求时显示已有阶段，不能为了诊断再次提交。现有全量日志下载和清空菜单保留。使用明确错误分类提示下一步，等待人工验证不使用“签到失败”标题。

### 11. 权限与验证保持最小范围

按所选实现补充 `GM_addValueChangeListener`、`GM_removeValueChangeListener`、`GM_listValues` 和 `GM_deleteValue`，保留现有 `GM.deleteValue` 兼容调用；相关能力缺失时走有界降级。核对 GM 存储调用风格、@grant 与管理器运行能力，不新增 @connect 或站点匹配，不在本次去除 jQuery 或整理不相关权限。

新增轻量 `tools/forum-signin/` 回归入口，采用 Node assert、VM 和已有 Playwright。检查行为而非函数文本：假成功反例、重复操作请求计数、超时与结果未知、重置后迟到结果、导入回滚、跨日及 UI 不打断。浏览器隔离页覆盖真实事件传播、中文输入事件序列、节点稳定和样式数量。

有可访问站点时再做登录、验证码及真实签到确认；无法现场验证的适配以保存的脱敏 DOM/响应样本验证，并在交付中注明。不能把样本测试或静态检查称为在线站点签到成功。

## Risks / Trade-offs

- [保守确认会增加待确认数量] → 为结果未知提供重新检查和手动标记，优先补齐站点专属证据；不恢复默认假成功。
- [GM 缺少跨来源原子互斥] → 同实例确定防重、跨实例租约协调、提交前检查与未知结果停止重提，保留极端竞争限制。
- [页面后台节流或跨域登录丢失任务关联] → 回到可见时补查、过期后先检查结果、关联不明时保留页面不关闭。
- [保留挂载节点增加少量视图管理逻辑] → 只维护目标行、搜索和配置草稿，不引入框架或全局重构。
- [历史清理或导入影响已有数据] → 默认不清理、明确预览、导入前快照与失败恢复，限制输入规模。
- [网站调整文案或结构] → 将必要证据集中在站点适配中，保留分类诊断；真实页面变化需要后续适配维护。

## Migration Plan

1. 先建立针对现有问题的隔离回归样例，再增加目标状态兼容读取、操作代次和恢复入口。
2. 引入结果结构和检查/执行边界，修复四个优先站点并逐一回归其余既有站点；未完成确认能力前不依赖其自动关闭。
3. 接入统一任务入口、分类重试与独立页面任务关联，再更新控制台挂载、监听和状态相关操作。
4. 最后接入备份恢复、可选历史清理及单站点诊断，完成多页面及异常恢复验证。
5. 升级首次读取时保留旧 key 和未知来源记录；新能力渐进写入可选字段，旧版回退仍能读取设置和成功日期，但不会支持新任务元数据。
6. 需要回退时先导出配置及状态，停用新脚本后再安装旧版；历史清理不可从已删除数据凭空回退，需要用户保存的历史备份。导入未完成事务先使用恢复快照处理。
7. 本次规划不升版、不更新 README 或 CHANGELOG。实施完成且用户要求收尾或提交时，按新增功能升次版本，统一核对脚本元信息、README 和一个 CHANGELOG 版本小节。
