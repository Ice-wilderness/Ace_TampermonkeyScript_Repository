# bilibili-history-manager-ui Specification

## Purpose

为设置、历史管理、统计三个页签及公共弹窗提供完整统一的视觉与交互体验，使日常配置、记录检索和数据操作具有清晰层级、即时反馈及键盘和窄屏可用性，并保留现有用户功能。

## Requirements

### Requirement: 管理面板采用完整统一的视觉体系
管理面板 MUST 重新组织布局、导航、排版、间距、表单、按钮和状态反馈，使用深石墨导航、暖白内容背景与蓝色主操作，三个页签及公共弹窗 MUST 使用一致的视觉规则。

#### Scenario: 桌面打开管理面板
- **WHEN** 用户在桌面视口通过现有入口打开管理面板
- **THEN** 系统 MUST 默认显示设置页，提供清晰的侧栏导航、页标题、内容区和关闭入口
- **AND** 三个页签 MUST 具有可识别的当前选中状态和一致的控件样式

#### Scenario: 空数据与有数据均可展示
- **WHEN** 用户分别查看空历史、少量记录和大量记录
- **THEN** 三个页签 MUST 提供适合当前状态的布局，不得依赖虚构统计数字或真实视频封面才能成立

### Requirement: 设置页具备明确分组与样式预览
设置页 SHALL 将现有配置组织为播放与提示、页面标记、标签样式和诊断维护等清晰分组，并提供仅作用于预览区的实时标签预览。

#### Scenario: 修改标签样式草稿
- **WHEN** 用户调整位置、透明度、进度条或阈值
- **THEN** 预览区 MUST 即时展示对应效果，覆盖已访问、不同观看进度及多 P 状态
- **AND** 保存前 MUST 不写入正式设置，也不得改变页面上真实视频的标记

#### Scenario: 所有既有设置与维护操作可访问
- **WHEN** 用户使用新设置页
- **THEN** 原有显示开关、续播提示、悬浮按钮隐藏规则、透明度、位置、低高阈值、调试日志、下载及清空日志、恢复面板位置和适用时的当前视频跳转 MUST 继续可用

### Requirement: 设置草稿与保存状态可见
系统 MUST 在面板会话内保留设置草稿，明确展示未保存、保存中、已保存和保存失败状态，并让保存与恢复默认入口始终易于找到。

#### Scenario: 编辑设置后切换页签
- **WHEN** 用户编辑设置但未保存，切换到历史管理再返回
- **THEN** 草稿 MUST 保留，且未保存状态 MUST 仍然可见

#### Scenario: 输入非法阈值
- **WHEN** 低高阈值为空、不是有限整数、超出 1 至 99 或低阈值不小于高阈值
- **THEN** 系统 MUST 显示字段旁错误并阻止保存，正式设置 MUST 保持原值

#### Scenario: 恢复默认设置
- **WHEN** 用户选择恢复默认设置
- **THEN** 默认值 MUST 进入当前草稿并更新预览，用户保存后才应用到正式设置

#### Scenario: 带未保存修改关闭面板
- **WHEN** 用户存在设置草稿修改并尝试关闭面板
- **THEN** 系统 MUST 提供保存后关闭、放弃修改和继续编辑的清晰选择
- **AND** 保存失败时 MUST 保留面板和草稿

### Requirement: 历史管理呈现清晰的查询与批量操作层级
历史页 MUST 清晰区分搜索筛选、数据列表、批量操作、分页和数据维护，保留现有搜索、排序、分页、多选、删除撤销、导入导出及保留周期清理能力。

#### Scenario: 选择多条历史
- **WHEN** 用户选中一条或多条记录
- **THEN** 系统 MUST 显示选中数量和相关批量操作
- **AND** 当前页全选框 MUST 正确反映全选或部分选中状态，零选中时删除选中 MUST 不可执行

#### Scenario: 查询无结果
- **WHEN** 用户的搜索或筛选条件没有匹配记录
- **THEN** 系统 MUST 展示无匹配结果反馈并提供清除条件入口，且不得与尚无任何历史的空状态混淆

### Requirement: 统计页具备一致且准确的展示层级
统计页 MUST 保留已有统计卡片、状态及进度分布、近期趋势和范围切换能力，并以统一的数字、标签、坐标及状态色展示。

#### Scenario: 切换统计时间范围
- **WHEN** 用户在 7、30、90 天之间切换
- **THEN** 图表标题、范围状态、数值和空状态 MUST 同步更新
- **AND** 图表 MUST 提供可读说明，不能仅依赖颜色表达状态

### Requirement: 公共弹窗与操作反馈一致
系统 SHALL 为确认、加载、成功、失败及撤销提供统一的可交互反馈，并确保确认和进度信息在管理面板上方可见。

#### Scenario: 确认保留周期清理
- **WHEN** 用户请求清理且存在候选记录
- **THEN** 二次确认 MUST 明确显示保留周期、截止时间和预计删除数量
- **AND** 取消 MUST 不删除数据；该流程 MUST 保留现有保留周期清理规范的全部约束

#### Scenario: 操作失败
- **WHEN** 保存、导入、同步或删除失败
- **THEN** 界面 MUST 展示失败状态与可用的重试或关闭操作，解除进行中状态，并保留仍可恢复的输入或备份

#### Scenario: 删除完成后撤销
- **WHEN** 删除成功且处于现有撤销期限内
- **THEN** 系统 MUST 提供文字明确、可用键盘触发的撤销按钮，不能仅让整块提示消息承担隐式点击操作

#### Scenario: 撤销需要等待存储
- **WHEN** 用户点击撤销而恢复操作尚未完成
- **THEN** 系统 MUST 立即展示进行中反馈并阻止重复提交，持续到真实完成或失败
- **AND** 失败 MUST 提供重试反馈，成功 MUST 按实际恢复和跳过数量报告

### Requirement: 键盘与窄屏可用
面板 MUST 具备可访问名称、正确的焦点管理、键盘导航及可见焦点样式，并在桌面和 390 像素宽视口中保持完整可用。

#### Scenario: 使用键盘打开与关闭
- **WHEN** 用户打开面板并用 Tab、Shift+Tab 和 Escape 操作
- **THEN** 焦点 MUST 进入面板并限制在当前顶层弹窗中，Escape MUST 只处理最上层弹窗
- **AND** 关闭后焦点 MUST 回到仍存在的触发入口

#### Scenario: 窄屏查看历史和设置
- **WHEN** 视口宽度为 390 像素或用户放大页面
- **THEN** 导航 MUST 调整为顶部布局，设置控件与关闭保存入口 MUST 可见且可操作
- **AND** 面板 MUST 无整体横向溢出，历史和统计的必要横向滚动 MUST 限制在各自内容区域

#### Scenario: 用户要求减少动态效果
- **WHEN** 系统启用减少动态效果偏好
- **THEN** 面板 MUST 关闭非必要位移和入场动画，操作状态仍须清晰

### Requirement: 页面隔离与现有入口兼容
新界面 MUST 仅作用于脚本自己的界面区域，保留现有入口与悬浮按钮隐藏规则，不增加页面请求或依赖外部视觉资源。

#### Scenario: 管理面板与 Bilibili 原页面共存
- **WHEN** 用户在现有匹配页面打开、操作并关闭管理面板
- **THEN** 原页面导航、播放器、按钮和布局 MUST 不被脚本的面板样式污染
- **AND** 关闭后原页面滚动状态 MUST 恢复，观看记录功能 MUST 继续运行
